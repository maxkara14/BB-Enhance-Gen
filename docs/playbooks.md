# Проверка Enhance Gen

## Локальные автоматические проверки

Запускать из каталога расширения. Runtime-зависимости не добавлены.
Для тестов нужны Node.js 22+ и установленный Chromium/Chrome/Edge.

```powershell
node --check index.js
node --check core.js
node --check ui.js
node --test tests/core.test.mjs
node tests/browser-runner.mjs
git diff --check
```

Браузерный runner автоматически находит Chrome/Edge в стандартных каталогах
Windows. При другом расположении задать `CHROME_PATH` (это необязательная
переменная только для тестов):

```powershell
$env:CHROME_PATH = 'C:/path/to/chrome.exe'
node tests/browser-runner.mjs
```

Мобильный viewport 375×667 и снимок синтетического предпросмотра:

```powershell
$env:ENHANCE_MOBILE = '1'
$env:ENHANCE_SCREENSHOT = Join-Path $env:TEMP 'bb-enhance-mobile.png'
node tests/browser-runner.mjs
Remove-Item Env:ENHANCE_MOBILE, Env:ENHANCE_SCREENSHOT
```

Без `ENHANCE_MOBILE` используется viewport 1280×900. Runner запускает скрытый
headless-браузер с отдельным временным профилем и локальным HTTP-сервером,
затем закрывает их и удаляет только созданный профиль. Скриншот, если задан,
остаётся по указанному пути. Пользовательский профиль браузера не используется.

## Что проверяется

- SSE: границы UTF-8, последний фрагмент без перевода строки, завершение,
  обрыв, malformed data, фильтрация, лимит длины, отмена и пустой ответ.
- JSON FT/TS: типы, обязательные поля, три варианта, корректный запрет.
- Сохранение обычного текста и реплик; очистка служебных вставок и reasoning.
- Настоящие ES-модули расширения в браузере: настройки → нажатие кнопки →
  формирование запроса → обработка ответа → предпросмотр → применение/отправка.
- Изменение черновика, переключение чата, повторный запрос, Escape, фокус,
  Tab, отказ native generation, тайм-аут, возврат оригинала и fallback.
- Редактирование/обновление FT/TS, авторский обход запрета, ручной бросок,
  раздельная история чатов, локализация и безопасный вывод модельного текста.

API и чат в стенде синтетические. Запросы не достигают провайдера или
пользовательского сервера. Docker не используется: это клиентское расширение,
проверяемое непосредственно в браузере; контейнерная архитектура не меняется.

## Проверенные интеграционные API

Сигнатуры сверены с установленными `public/scripts/st-context.js`,
`public/script.js`, `public/scripts/authors-note.js` и расширением `memory`.
События и общий способ интеграции дополнительно сверены с
[документацией UI extensions](https://docs.sillytavern.app/for-contributors/writing-extensions/).

- `getCurrentChatId`, `characters[characterId].avatar`, `groupId` — идентичность чата.
- `generateQuietPrompt({ quietPrompt, responseLength })` — служебная генерация.
- `generate('normal' | 'swipe')`, `stopGeneration()`, `saveChat()` — отправка,
  ожидание генерации, остановка и сохранение изменённого сообщения.
- `CHAT_CHANGED`, `GENERATION_STARTED`, `GENERATION_ENDED`, `GENERATION_STOPPED`.
- `accountStorage.getItem/setItem/removeItem` — история в аккаунте.
- `extensionPrompts['2_floating_prompt'].value`, `['1_memory'].value` —
  доступные заметка автора и summary; при отсутствии используются пустые строки.

## Ограничения и ручная проверка

Стенд не проверяет качество художественного результата, CORS конкретного
провайдера, реальные серверные ошибки, особенности групповых генераций и
взаимодействие со всеми сторонними расширениями/темами. Эти сценарии требуют
проверки в выбранном пользователем тестовом чате.

У `generateQuietPrompt` нет параметра AbortSignal: отмена делегируется
`stopGeneration`, затем расширение ждёт завершения native promise. Этот API
возвращает только текст, без `finish_reason`; обнаружение лимита ответа по
метаданным доступно для Custom API, а не для основной модели. При отмене уже
начатой отправки SillyTavern может сохранить отправленное сообщение или
частичный ответ бота; расширение не удаляет их автоматически.

Проверка после обновления SillyTavern: в отдельном чате выполнить Enhance,
Improve, Director «Мне/Боту», бросок с черновиком и без, FT/TS, сменить чат
во время служебного запроса. Проверить остановку основной модели, новый свайп,
сохранение подсказки после перезагрузки и отсутствие посторонних сообщений.
